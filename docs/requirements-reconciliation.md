# Сверка с ТЗ «Кейс 4» и паспортом OE-04 (ред. 0.4)

Фаза 02 (дизайн-система) учла требования ТЗ к интерфейсу. Расхождения движка и данных фазы 01 с документами — к исправлению в следующей фазе:

| Требование ТЗ | Сейчас (ruleset v1.0.0) | Действие |
| --- | --- | --- |
| История 24 последовательных месяца | 30 суток | `checkPeriodMonths: 24`, проверка покрытия по месяцам с перечнем недостающих |
| Шаг данных 15 мин | 30 мин | `intervalMinutes: 15` |
| Дубли временных меток, единицы, знаки | не проверяются | новые правила |
| Связь с объектом по EAN из паспорта | нет | правило привязки |
| Телеметрия: полнота ≥ 99 % за 48 ч | 95 % / 24 ч | пороги в конфиг |
| Актуальность: последнее значение ≤ 30 мин от точки проверки | задержка доставки 30 с | заменить правило на «свежесть» |
| Сигналы по активам PV/Battery/Grid/Demand из object.json | абстрактные сигналы | модель актива по паспорту |
| Управление: setpoint_sent → setpoint_received → изменение мощности | команды с квитированием | правило по сигналам telemetry.csv |
| 4 блока дашборда: история учёта, текущие активы, управление, качество/статус | типы блоков KPI/… | смысловые блоки + привязка к объекту + права |
| Статусы проверки «не применимо», «неактуально», «источник недоступен» | нет в домене | поддержано в UI (CheckStatus), добавить в движок |
| Изменение входов делает подтверждения неактуальными | нет | инвалидация подтверждений |
| Импорт CSV: `;`, десятичная `,`, UTF-8 BOM, единица в имени колонки | `,` и long-формат | адаптер импорта |
| 11 тестовых сценариев, 6 объектов | 7 сценариев, 1 объект | привести каталог сценариев |
| Единицы кВт/кВт·ч, Europe/Brussels | МВт, Europe/Moscow | демо-данные |
