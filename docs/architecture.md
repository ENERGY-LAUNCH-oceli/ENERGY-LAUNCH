# Архитектура

SPA без сервера: React 19 + TypeScript, Vite 7, Tailwind 3, Zustand, Dexie (IndexedDB), PapaParse, Zod.
Вся логика проверок – чистые функции в `src/engine`; интерфейс только показывает результат и вызывает действия.

## Слои

```
Presentation ─▶ Business logic ─▶ Data
pages, features,   src/engine          src/data, src/services,
components, store  (без React/сети)    src/simulator
        └──────▶ src/types · src/schemas · src/config ◀──────┘
```

| Слой | Каталоги | Правило |
| --- | --- | --- |
| Интерфейс | `app/`, `pages/`, `layouts/`, `components/`, `features/`, `hooks/` | Без порогов и проверок в компонентах |
| Хранилище | `store/launch-store.ts` | Тонкий адаптер: вызывает движок, кладёт результат в состояние, пишет в IndexedDB; проверяет права роли |
| Движок | `engine/state-machine`, `engine/validators`, `engine/invoice`, `engine/telemetry`, `engine/control`, `engine/dashboards`, `engine/trail` | Чистые функции; время и ID – через `EngineContext`, поэтому прогоны воспроизводимы |
| Данные | `data/case4` (набор кейса), `data/mock` (генераторы), `data/objects` (каталог), `services` (Dexie, импорт CSV) | Валидация входа – Zod |
| Имитатор | `simulator/control` | Модель стенда для тестов управления; без сети и таймеров |
| Сценарии | `scenarios/` | Каталог 11 сценариев ТЗ, песочницы, прогон через действия хранилища |
| Конфигурация | `config/rules` | Версии наборов правил – единственное место порогов |

## Поток данных

1. **Старт.** `App` показывает прелоадер и вызывает `bootstrap()`. Если есть `public/case4/manifest.json`, Web Worker
   (`data/case4/case4.worker.ts`) читает и разбирает CSV потоково (PapaParse) – главный поток не блокируется.
   Готовый портфель применяется в момент статичной фазы прелоадера. Без набора – синтетический портфель.
2. **Каталог.** `data/objects/catalog.ts` – объекты (`source`: `CASE4`, `SYNTHETIC`, `SCENARIO`) и их входы.
   Песочницы сценариев живут в отдельном каталоге и в портфель не попадают.
3. **Сессия запуска.** У каждого объекта своё рабочее пространство: `LaunchSession` (этапы, блокеры, подтверждения),
   `LaunchInputs` (версии входов, история проверок) и журнал аудита.
4. **Действие** (начать этап, проверить, подтвердить, завершить, загрузить файл, тест управления, публикация,
   приёмка) → функция движка → `{ ok, session | error, events }` → состояние + IndexedDB.
5. **Изменение входа** (новая выгрузка, паспорт, тест, публикация) → `invalidate()`: подтверждения затронутых
   этапов помечаются устаревшими, начатые этапы перепроверяются (снимок с `trigger: RECHECK`).

## След проверок (`engine/trail`)

- `ValidationSnapshot` – каждый прогон: входы (вид, версия, файл, строки, SHA-256), версия правил, результаты,
  статус до и после, причина и инициатор.
- `blockerRecord()` – карточка препятствия: что случилось, почему, ожидалось / фактически, использованные данные,
  правило с параметром, как исправить, что будет перепроверено.
- `evidenceRecords()` – подтверждения с актуальностью: `CURRENT`, `SUPERSEDED`, `STALE`.
- `auditRecords()` + `stateAt()` – журнал «было → стало» и воспроизведение статусов объекта на любой момент.

## Производительность

- Разбор CSV набора (≈ 70 000 строк на объект) – в Web Worker; анализаторы потоковые, в состоянии хранится отчёт, а не строки.
- Страницы грузятся по маршруту (lazy routes); в основном пакете – оболочка, обзор, движок и хранилище.
- Таблицы журналов ограничены по числу строк с догрузкой.

## Дизайн

Минималистичный интерфейс; от Oceli Energy – только палитра. Токены светлой и тёмной темы – `src/design/tokens.ts`,
Tailwind генерирует из них CSS-переменные `--el-*`. Тема по умолчанию светлая; выбор хранится в `localStorage`
и применяется до загрузки (`public/theme-init.js`). Шрифты – Inter, Inter Tight, JetBrains Mono (локально, @fontsource).
