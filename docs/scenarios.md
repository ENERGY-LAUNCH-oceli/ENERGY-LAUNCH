# Сценарии

Страница `/scenarios` и тест `tests/unit/scenarios.test.ts` запускают 11 сценариев ТЗ (раздел 6.3, паспорт OE-04 раздел 4).

## Как устроено

- **Песочница.** Каждый сценарий получает собственный объект `scenario-NN` и набор данных, сгенерированный
  детерминированно (`src/scenarios/sandbox.ts`): синтетический объект с PV1 и Battery1, корректными EAN и
  параметрами дефекта (короткая история, пробелы, молчащий актив, чужой object_id…). Исходные файлы набора кейса
  и демо-данные не изменяются.
- **Настоящий механизм.** Шаги (`src/scenarios/catalog.ts`) вызывают те же действия хранилища, что и кнопки
  интерфейса: начать этап, проверить, подтвердить, завершить, тест через имитатор, публикация и приёмка панели,
  смена роли, новая выгрузка, недоступный источник. Статусы считает движок по входам и версии правил.
- **Ожидаемое – только для сравнения.** Ожидаемые статусы и препятствия из ТЗ лежат в описании сценария и в
  вычисление статусов не передаются.
- **Изоляция и воспроизводимость.** Прогон сохраняет и восстанавливает состояние пользователя, уведомления
  отключены, запись в IndexedDB не ведётся. Повторный прогон начинается с чистого листа (**Reset Scenario** – кнопка
  ↺ удаляет результат). Одинаковые входы дают одинаковый результат (проверяется тестом).
- Результат прогона можно открыть как объект («Открыть объект сценария»): карточка запуска, проверки, журнал.
  В портфель песочницы не попадают.

## Метрики (ТЗ 6.1)

| Метрика | Расчёт |
| --- | --- |
| Верность статусов | совпавшие статусы / (4 × число сценариев) |
| Найдено препятствий | найденные обязательные / все обязательные |
| Ложных завершений | этапы COMPLETED с блокирующим провалом в последней проверке; цель 0 |
| Покрытие подтверждениями | обязательные проверки завершённых этапов с источником, результатом, временем и версией правила |

**Сравнение с ручной проверкой (ТЗ 6.1 п. 5, 6.2).** Те же 6 оценочных сценариев. Инженер выгружает «Ручной чек-лист»
(CSV из каталога правил действующей версии – правила совпадают с прототипом), проверяет объект сценария вручную и засекает
время секундомером в строке сценария, затем – с прототипом. ΔT = (Tручн − Tпрот) / Tручн × 100 % по медианам, цель ≥ 30 %.
Если время с прототипом не замерено, берётся длительность прогона сценария (нижняя граница). Пока ручное время не замерено
по всем шести, ΔT – «не измерено»: значения не подставляются. Замеры хранятся в браузере; «Результаты CSV» – выгрузка таблицы.

## Добавить сценарий

1. Описать набор в `SandboxSpec` (параметры генераторов `buildInvoiceDataset` / `buildTelemetryDataset`).
2. Добавить `ScenarioDef` в `SCENARIOS`: вход, ожидаемое, `expectedStatuses`, `expectedBlockers`, `steps`, `checks`.
3. `npm test -- scenarios`.
