# Страницы состояния и «Нет подключения»

## Что есть

| Где | Что показывает |
| --- | --- |
| `/errors` | Справочник: все коды HTTP из реестра IANA (1xx–5xx, 63 кода) и «Нет подключения» |
| `/errors/<код>`, `/errors/offline` | Страница кода внутри приложения |
| любой несуществующий адрес | Страница 404 |
| `/status/<код>.html` | Статическая страница: её отдаёт nginx (`error_page`), когда приложение не загрузилось или служба API не отвечает (502, 504 …) |
| `/offline.html` | Статическая страница «Нет подключения»: её показывает service worker, если страницу открыли или обновили без сети |
| экран поверх приложения | Связь пропала в открытой вкладке: данные на странице остаются, «Продолжить без сети» убирает экран до следующего обрыва, при возврате связи экран закрывается сам |

Тексты (что произошло и что делать) – `src/errors/codes.ts`; один источник для приложения, статических страниц и сборки.

## Анимации

`src/errors/animations.ts` – 13 анимаций на canvas в теме энергетики: обрыв линии, осциллограф трёх фаз,
энергосеть с отказом узла, ячейки накопителя, ветряки, солнечное поле, барабаны счётчика, частицы кода, поиск сигнала,
электрическая дуга, потерянные пакеты, интерференция волн, пульс сети.

- При каждой загрузке выбирается случайная анимация, не совпадающая с предыдущей (`sessionStorage`, ключ `el.status.anim`).
- Код состояния входит в анимацию (барабаны счётчика, частицы); цвет «сбоя» – цвет ошибки у 4xx, 5xx и офлайна.
- Цвета – из `src/design/tokens.ts`, обе темы и оба акцента; смена темы перерисовывает анимацию.
- «Уменьшение движения» в системе – один статичный кадр.
- Для проверки конкретной анимации: `?anim=<id>` (например `/status/502.html?anim=arc`).

## Сборка и сервер

- Плагин `statusPages` в `vite.config.ts` собирает `src/errors/static-entry.ts` в один файл `status/status.js`
  (строгая CSP: без встроенных скриптов) и создаёт `status/<код>.html`, `status/status.css`, `offline.html` и `sw.js`.
  В dev-сервере те же адреса отдаются на лету.
- `sw.js` перехватывает только переходы между страницами: сеть – первой, `/offline.html` – только когда сети нет.
  Приложение и `/api` не кешируются. Регистрируется только в рабочей сборке (не в dev и не в e2e).
- nginx: `error_page <код> /status/<код>.html` для кодов, которые он отдаёт сам (`deploy/nginx.conf`,
  `deploy/server/elaunch.nginx.conf`). Ответы приложения и API не подменяются.
