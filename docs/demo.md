# Демонстрация

Два пути: на реальном наборе кейса (6 объектов) и через страницу сценариев (работает всегда).

## 1. Полный путь объекта

**Через сценарий** – `/scenarios` → «Полный запуск» → «Запустить сценарий» → «Открыть объект сценария».
Карточка запуска показывает 4 завершённых этапа и «Объект готов к эксплуатации»; протокол – вкладка «Протокол»
(«Экспорт в PDF»).

**Вручную** (синтетический портфель: `VITE_DATASET=synthetic npm run dev`, `/objects/obj-001/launch`,
в селекторе «Демонстрационный сценарий» выбрать «Успешный запуск»):

1. Этапы 1–3 по очереди: выбрать этап → «Начать этап» → «Запустить проверки» → «Подтвердить требования»
   (отметить требования, «Подтвердить») → «Завершить этап». Тесты управления этапа 3 выполнены в имитаторе
   заранее; новый тест можно запустить на странице «Управление».
2. Этап 4: «Начать этап» → «Дашборды» → «Конструктор» → настроить блоки → «Опубликовать v1».
3. Меню профиля → роль «Ответственный за приёмку» → вкладка «Приёмка»: каждый из 4 блоков «Корректен» →
   «Принять панель v1». Роль «Оператор» может только смотреть.
4. Роль «Инженер запуска» → «Завершить этап»: «Объект готов к эксплуатации»; «Протокол» → «Экспорт в PDF».

Этот путь прогоняет e2e-тест «успешный запуск проходит все этапы через интерфейс».

## 2. Блокировка → исправление → повторная проверка

**Через сценарий** – «Исправление и повтор»: короткая история блокирует этап 1, новая выгрузка снимает блокировку
(MH-002 → RESOLVED), изменённый паспорт делает подтверждения неактуальными, завершение отклоняется до повторного
подтверждения. История прогонов сохраняется.

**Вручную** (синтетический портфель):

1. `/objects/obj-002/history` – этап 1 BLOCKED, недостающие месяцы 2024-11…2025-03, препятствие MH-002 с
   причиной и следующим действием («Препятствия» → карточка).
2. Загрузить исправленный файл («Полная история» или invoice.csv) – новая версия входа, автоматическая повторная
   проверка: месяцы покрыты, этап IN_PROGRESS, в «Истории проверок» два прогона.
3. «Аудит» → выбрать событие до загрузки: панель воспроизведения показывает статус BLOCKED и проваленное правило на тот момент.

Телеметрия: `/objects/obj-004/telemetry` – Battery1 «Нет связи» → «Корректный поток» → повторная проверка, этап разблокирован.

## На реальном наборе

Обзор показывает фактическое состояние Building1–6 после автоматических проверок этапа 1: что заблокировано и почему
(короткая история Building3 и Building6, знаки Building4, контрольная цифра EAN Building5 и т. д.). Подтверждения и
переходы выполняет человек – статусы без подтверждения не присваиваются.
