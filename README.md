# ENERGY LAUNCH

Платформа для сопровождения запуска энергетических объектов (кейс 4, паспорт OE-04).
Объект проходит четыре последовательных этапа – **история счётчиков → телеметрия в реальном времени →
тесты управления → финальные дашборды**. Каждый статус выводится только из входных данных и версии
правил, каждое действие пишется в журнал аудита, каждое препятствие объяснено и имеет следующее действие.

Управление реальным оборудованием исключено: команды этапа 3 уходят только в локальный имитатор.

## Быстрый старт

Требуется Node.js ≥ 20.19 (проверено на 22).

```bash
npm ci
npm run dev        # http://127.0.0.1:5173 – вместе с сервером хранилища (без DATABASE_URL – встроенный PostgreSQL в .data/)
```

Сервер хранилища встроен в dev-сервер; отдельно его можно запустить `npm run api` (127.0.0.1:8787) – тогда
`npm run dev` использует его. Без сервера приложение тоже работает, но ход запуска хранится только до перезагрузки
страницы. Хранилище, таблицы и API – [docs/storage.md](docs/storage.md).

Прод: https://elaunch.xroyse.ru – синтетический портфель, раскладка и обновление – [docs/deploy.md](docs/deploy.md).

Без набора кейса приложение работает на синтетическом портфеле. Как подключить реальный набор (Building1–6) –
[docs/data-upload.md](docs/data-upload.md).

### Docker

```bash
docker compose up --build   # http://127.0.0.1:8080
```

Три контейнера: `energy-launch` (SPA через nginx, строгая CSP, без карт исходников; `/api` проксируется),
`api` (сервер хранилища) и `db` (PostgreSQL 17, том `pgdata`). Перед запуском задайте `POSTGRES_PASSWORD` в `.env`.
Данные кейса в образ не входят:
`public/case4` монтируется томом только для чтения. Без папки – синтетические данные. Переменные – `.env.example`.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Dev-сервер Vite (127.0.0.1:5173) со встроенным сервером хранилища |
| `npm run api` | Сервер хранилища PostgreSQL (127.0.0.1:8787); `npm run dev:api` – с перезапуском при правках |
| `npm run build` | Проверка типов и production-сборка в `dist/` |
| `npm run typecheck` | TypeScript (`tsc -b`) |
| `npm run lint` | ESLint (typescript-eslint, react-hooks) |
| `npm test` | Unit- и интеграционные тесты (Vitest), включая 11 сценариев ТЗ и сервер хранилища на PostgreSQL (PGlite) |
| `npm run test:e2e` | E2E (Playwright: сборка `--mode e2e` на синтетике и preview на 127.0.0.1:4173) |
| `node scripts/case4-manifest.mjs` | `manifest.json` набора кейса: SHA-256, строки, период, шаг |

## Разделы приложения

| Маршрут | Назначение |
| --- | --- |
| `/overview` | Центр запуска: готовность всех объектов, что требует внимания |
| `/objects`, `/objects/:id` | Реестр объектов, паспорт (поля object.json, файлы набора с SHA-256) |
| `/objects/:id/launch` | Карточка запуска: этапы, следующее действие, журнал |
| `/objects/:id/history` · `telemetry` · `control` · `dashboards` | Рабочие страницы четырёх этапов |
| `/objects/:id/audit` · `protocol` | Журнал объекта; протокол готовности (экспорт в PDF) |
| `/blockers` · `/evidence` · `/audit` | Препятствия, подтверждения, сквозной журнал аудита с воспроизведением статуса |
| `/scenarios` | 11 демо-сценариев ТЗ, метрики качества, сравнение с ручной проверкой |
| `/help` | Обучение: урок и тур «Показать на сайте» по каждому блоку, вопросы и ответы, помощник по сайту ([docs/help.md](docs/help.md)) |
| `/settings` | Действующие правила проверок и интерфейс |
| `/me`, `/admin` | Личный кабинет сотрудника (профиль, свои действия, смена пароля); админ-панель: сотрудники, логины и пароли, роли, отключение, метрики. Окно входа – при работе с сервером; первый вход создаёт администратора |
| `/errors`, `/errors/:code` | Коды состояния HTTP и «Нет подключения»: одна страница для всех кодов, в стиле окна входа ([docs/status-pages.md](docs/status-pages.md)) |

Тема по умолчанию светлая, переключатель – внизу боковой панели. Роль (инженер запуска, оператор, ответственный
за приёмку) – в меню профиля.

Файлы можно бросить в любое место окна (или «Загрузить файлы»): система сама определит тип (паспорт, история,
телеметрия) и объект и разложит их по этапам – [docs/data-upload.md](docs/data-upload.md).

## Безопасность

- Реальные команды оборудованию невозможны: единственный транспорт – имитатор, движок отклоняет любой другой (`UnsafeTransportError`).
- Секретов, токенов и учётных данных в репозитории и логах нет; сетевой доступ – только чтение файлов набора с того же origin.
- Обязательные проверки нельзя обойти через интерфейс: переходы выполняет конечный автомат, права ролей проверяются в движке.
  Устаревшее подтверждение обновляется только после повторной проверки на текущих данных.
- Вкладка с устаревшим состоянием не затирает свежее: запись несёт ревизию, сервер отклоняет чужую (409).
- Текст во входных данных – только данные: он не влияет на статусы (сценарий 10).
- Данные кейса и документы ТЗ (`public/case4`, `docs/source`) не коммитятся и не попадают в образ (ТЗ 4.3).
